# Rufus Trivia × Three.js: Storyboard Proposal

## The three concepts

| Concept | Fit | Problem |
|---|---|---|
| **Pop-up storybook dioramas** | Each question becomes a page that folds up. It works for all six topics, and Mix is just a book with mixed chapters. Pixel foxes look right as flat paper cutouts, so no 3D character modeling is needed. | Without discipline it becomes pretty wallpaper. |
| **Constellation/planet journey** | Great for science/space. | Flags, books and math don't map onto planets, so it would feel forced for four of six topics. Dark scenes also hurt readability on phones. |
| **Neighborhood clue trail** | Strong narrative. | It implies that clues unlock the path, so wrong answers feel like blocked progress. That fights both "no punishment" and "outcomes are server-only". The art scope is also larger. |

**Recommendation: storybook dioramas.** They're the only option that is topic-agnostic and reuses the existing sprites as-is. A 9-year-old can also design them on paper first ("draw the page, then we build it"). I'd borrow one idea from the constellation concept: on the final page, your five answers light up as stars.

## 6-beat pilot storyboard (5 questions, Mix)

Dialogue appears only during **countdown** and **reveal**, never during **question**, so reading time goes to the question.

1. **Cover (countdown).** The book opens and Rufus pops up. *"Five pages. Let's read!"* The player just watches; this is the countdown.
2. **Flags page (Marthina).** A paper flag on a pole. Player taps an HTML answer. **Reveal:** the flag "unfolds" into its layers so you can see the stripe order. If wrong: *"Ooh, close! Watch: red, then white."*
3. **Animals page (Renard).** Answer: blue whale. **Reveal:** a paper whale slides in next to Renard for a size comparison. *"That's like 300 foxes long!"*
4. **Math page (Fiery).** 6 × 4. **Reveal:** 24 paper blocks drop into a 6×4 grid, then regroup as 4×6. *"Same blocks, either way!"*
5. **Space page (Rufus).** "Which planet is biggest?" **Reveal:** planets pop up to scale on a string. *"Jupiter could hold every other planet."*
6. **Books page, then The End (final).** The Q5 reveal is followed by the book closing, five stars lighting up the cover, and the existing score UI rendered in HTML on top.

**Wrong answers:** the reveal scene is *identical for everyone*. It always acts out *why* the answer is right. A wrong answer only adds a one-line HTML hook ("Close! Here's the trick…"), with no sad fox, no shake, and no red X animation. Each reveal teaches whether or not you got it right.

**What Three.js actually adds:** spatial explanation through layering, scale, grouping and order. If a page's reveal doesn't explain something, cut the 3D for that page. That is the test for every diorama.

## Constraints

- **HTML owns interaction.** Question text and buttons are HTML layered over the canvas. Buttons enable the moment server state says `question`, regardless of animation state.
- **Server owns time.** Animations read progress from `(now − phaseStart) / phaseDuration` using server timestamps. Late joiners jump to the correct frame, and animations never `await`.
- **Equal timing.** Every reveal animation must finish within the shortest reveal window. Everyone sees the same scene, chosen by question topic and ID.
- **390px layout.** Canvas takes the top ~40vh, with question and buttons below. Cap devicePixelRatio at 2, use under ~30 meshes per page, and render sprites with `NearestFilter` so the pixel art stays crisp.
- **Reduced motion.** Static camera, crossfades instead of folds, and the final pose of each reveal shown immediately.
- **WebGL failure.** Load Three.js with a dynamic `import()` after the lobby. On any failure, keep the current UI unchanged, optionally with a static PNG of each page. The game must be fully playable with the stage absent.
- **No AI during play.** All dialogue is authored JSON. Line variants are picked deterministically from the question seed.

## Schema

```json
{
  "id": "pilot-mix-1",
  "cover": { "fox": "rufus", "line": "Five pages. Let's read!" },
  "pages": {
    "flags":   { "fox": "marthina", "scene": "flagUnfold",
                 "reveal": { "lines": ["Watch the stripes stack up!"],
                             "wrongHook": "Close! Here's the trick:" } },
    "math":    { "fox": "fiery", "scene": "blockGrid",
                 "params": { "from": "question.operands" } }
  },
  "final": { "scene": "bookCloseStars" }
}
```

Scenes are keyed by **topic**, and the reveal reads parameters from the existing question payload. This means **no server changes for the pilot.**

## Integration boundary

Create a single new module, `story-stage.js`:

```
mount(containerEl) → bool   // false = WebGL unavailable
setPhase(phase, serverState) // pure read, idempotent
dispose()
```

It never writes state, never sends messages, and never touches scoring. Put it behind `?story=1`. **Commit the current uncommitted work first** so the pilot is a clean, revertable diff.

## Risks

- **Scope creep** is the biggest risk. Six topics times custom reveals is a lot of scenes. The pilot needs five scenes; stop there and playtest.
- **Generic reveals.** Some questions, like "Who wrote X?", have no spatial explanation. Books may need a simple generic "page flips to the cover art" reveal, and that's fine to admit.
- **Params coupling.** Math reveals need structured operands. If questions are currently only strings, that's a small server payload change; flag it rather than parsing text.
- **Bundle size.** Three.js is roughly 150 KB gzipped. That's acceptable when lazy-loaded, but don't pull in the examples or addons casually.
- **Small screens.** Dialogue bubbles over the canvas compete with the HTML at 390px. Prefer a single caption line in HTML.


## Codex review of the proposals

- Do not ship the proposed “300 foxes” whale comparison or “Jupiter could hold every other planet” claim without checking precise units and sources. Neither is included in the prototype.
- “No server changes” is conditional: publicQuestion currently lacks structured operands. Only add validated reveal metadata after server reveal; never parse question prose or leak answers before submission.
- Do not commit someone else’s existing uncommitted work. The experiment is isolated and not pushed.
- The sample reveal uses four rows of six blocks instead: exact arithmetic, authored fixture, no model calls in play.
